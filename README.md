# 小说辅助系统
![alt text](image.png)
一个采用纸质阅读风格的多书籍小说创作辅助系统，包含写作、RAG 资料管理、章节/分卷总结和 AI 生图。后端为 Node.js + Express，前端为原生 HTML/CSS/JavaScript，无构建步骤。

## 功能说明

### 多书籍

顶部“当前书籍”选择器决定所有操作的目标书籍：

- 切换书籍后，写作区加载该书独立的定稿、草稿、章节名和召回编辑状态；
- 资料页只显示该书的资料目录；
- AI 提示、补全、章节总结、术语更新和分卷总结都携带当前书籍；
- 点击“新建书籍”可创建完整本地目录并自动切换。

每本书使用以下结构：

```text
RAG/<书名>/
  characters/                人物设定
  plots/
    volumes/                 分卷总结
    chapter-bodies/          章节正文
    chapter-summaries/       章节总结
  settings/                  术语与其他设定
```

原有单书资料已迁移到 `RAG/example/`。旧版 `plots/chapters/` 会合并到章节总结目录；遇到同名不同内容时使用“迁移冲突”后缀保留两份，不会覆盖。

### 写作页

- **阅读区**：显示已定稿正文。划选文字并点击“放回编辑区”后可修改，点击“确认替换”会按段落索引和段内偏移放回原位置。
- **编辑区**：写作或输入简要大纲；“确认归稿”把普通草稿追加到阅读区。
- **AI 提示**：结合当前书籍、已定稿正文和草稿给出建议。
- **AI 补全**：将编辑区大纲扩写为正式小说正文并写回编辑区。
- **总结本章**：先保存本章完整正文，再读取该书 `settings/术语.md`，生成章节总结和完整更新版术语。

写作状态保存在 `data/writing/<书名>.json`，不同书籍互不影响。

#### 自动章节编号

章节编号由服务器扫描当前书籍的章节正文与总结后计算，旧版 `第一章.md` 等中文数字文件名也会参与编号：

- 未填写标题：`第1章`、`第2章`……
- 填写“雨夜来客”：`第1章：雨夜来客`
- 即使用户自行输入了“第3章：雨夜来客”，服务器也会去掉手填编号并使用当前正确的下一章编号。

总结成功后，最终章节名会回填页面。正文与总结分别保存到：

```text
RAG/<书名>/plots/chapter-bodies/<最终章节名>.md
RAG/<书名>/plots/chapter-summaries/<最终章节名>.md
```

### 资料页与分卷总结

资料页支持查看、编辑、保存和新建当前书籍下的 Markdown 文件。

点击“分卷总结”后：

1. 页面显示下一合法卷号和现有章节总结；
2. 选择本卷包含的连续章节；
3. 服务器校验卷号、章节连续性、章节总结是否存在以及是否已归入旧卷；
4. AI 读取此前全部分卷总结和本卷所选章节总结；
5. 保存为 `RAG/<书名>/plots/volumes/第x卷：起-止.md`。

卷号不正确、章节不连续、重复归卷或缺少章节总结时只会提示错误，不调用 AI，也不产生文件。

### 生图页

- “优化提示词”读取 `image-prompt-optimize` 伪 skill；
- “生成图片”调用 `.env` 配置的生图接口；
- 图片保存于 `public/generated/`。

## 伪 skill

本项目中的 skill 是文件化 prompt，因此称为“伪 skill”。它们不是标准 Agent Skill，不执行工具或工作流，只把 `SKILL.md` 正文作为模型 system prompt，模型输出仍为纯文本。

```text
skills/
  writing-hint/SKILL.md
  writing-complete/SKILL.md
  chapter-summary/SKILL.md
  volume-summary/SKILL.md
  image-prompt-optimize/SKILL.md
```

服务器不再提供内置默认提示词。伪 skill 文件缺失或正文为空时，对应功能会返回明确配置错误。可以直接编辑这些文件调整 AI 行为。

章节总结伪 skill 使用固定纯文本分段：

```text
【章节总结】
...

【更新后术语】
...
```

后端只有成功解析两个非空区段后才会覆盖术语；解析失败时已经保存的章节正文仍会保留，原术语不会被破坏。

术语表与章节总结职责分离：章节标题、章节经过和剧情复盘只进入章节总结。术语表采用“宁缺毋滥”原则，人物只保留身份、稳定关系、长期特征及极简必要事实；组织、地点、环境、物品等只收录本书特有且后续写作需要依赖的设定，不记录常识、普通实体、临时状态，也不设置“规则”或“关键事件”栏目。本章没有可靠新术语时，伪 skill 必须原样返回已有术语，不为更新而更新。

## 运行方法

```bash
npm install
npm start
```

浏览器访问 `http://localhost:4000`（以 `.env` 中 `PORT` 为准）。开发时可运行 `npm run dev`。

## 目录概览

```text
server/                 后端路由、存储与 AI 服务
public/                 单页前端、样式与生成图片
skills/                 纯文本伪 skill
RAG/<书名>/             按书籍隔离的 Markdown 资料
data/writing/           按书籍隔离的写作状态
```

## 注意事项

- `.env` 含 API 密钥，不要提交到公共仓库。
- 书名拒绝路径分隔符和 Windows 非法文件名字符。
- 资料文件路径由后端限制在 `RAG/<当前书籍>/` 内，不能跨书或访问项目其他文件。
- 创建同名书籍会失败，不会覆盖已有资料。
